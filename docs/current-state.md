## 当前实现

- `FluxEngine` 管理共享环境和播放器，`Player` 提供公开命令、事件和绑定属性。
- `PlaybackPipeline` 独占每代解复用、解码、音频设备和帧泵。
- `PlaybackSeekController` 合并最新目标；`PlaybackSeekFrame` 独立等待当前跳转首帧。
- 数据包与视频帧使用代次，Seek 或管线退役后旧帧失效。
- `PlaybackRecordingController` 管理跨管线录制。
- `FluxMediaLog` 是独立静态日志入口。
- `FFmpegLibraries` 集中维护库名和 ABI，两个库共用绑定版本属性。
- `IsExternalInit` 在 Shared 中维护一份源码，分别编入两个 netstandard2.1 库。

## 最新修改与待确认

最新一轮根据用户日志修改了旧帧误判、新首包丢弃、首帧重缓冲和呈现等待。
新增 TimelineId 用于关联核心出帧和 Avalonia 显示提交。
**这些修改尚未构建或运行验证，不能引用历史通过次数证明当前源码正确。**

点播允许 Seek，直播由核心拒绝，即使自定义 UI 允许拖动也不能绕过。
目前以有限总时长判断点播，未知总时长的网络源保守禁止 Seek；DVR 等边界需结合新日志确认。

任意 FFmpeg 主版本适配仍是未完成目标。当前仍直接依赖 AutoGen 的结构布局，
库名集中管理不等于能随意替换不同 ABI 的 DLL。
Linux/macOS、HLS/UDP、设备切换和长稳同样不能凭短时 Windows 记录宣称通过。
